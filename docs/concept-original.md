# 『変数を見極めろ』ゲーム設計書

> 仕事の成果を「隠された関数」と捉え、何が変数で何が定数かを見抜くシミュレーションゲーム。
> 表向きはリソース配分パズル、その実態は **ノイズ込みの観測データから隠れた係数構造を推定するゲーム** である。

---

## 1. コンセプトと「ゲームの正体」

プレイヤーに見えているのは **入力（時間配分）** と **出力（成果%）** だけ。その間にある係数は伏せられている。プレイヤーは毎年データを1点ずつ取りながら、「どの要素が成果に効く変数で、どれが効かない定数か」を推定していく。

このゲームのジャンルは「最適化」ではなく **システム同定（隠れた構造の推定）** である。現実では誰も「これが定数だよ」と教えてくれない——その非対称性こそが体験の核になる。

### コアとなる緊張

10ターン（10年）しかないのに、メカニクスは徹底的に「沼」である：

- ノイズが重く、1年のデータは信用できない
- 要素同士が交差項で絡む（前提条件が複雑）
- 時間配分と信頼ポイントの二重管理が必要

素朴にやれば詰む。だから **情報を取りに行く年** と **成果を取りに行く年** はトレードオフになり、両方は欲張れない。この「全部は綺麗に解けない」というジレンマがプレイヤーに突きつける本質的な選択である。

### 設計の基本方針

- **メカニクスは沼**（ノイズ重い・交差項あり・二重管理）
- **勝敗判定はシンプル**（最終的な部署成果%のみ）

複雑さは過程に閉じ込め、結果は明快にする。プレイヤーが最後に見る数字は一つだけなので「自分が何点だったか」は一目でわかる。

---

## 2. 全体構造

| 項目 | 内容 |
|------|------|
| 総ターン数 | 10ターン（社会人1年目〜10年目） |
| 1ターンの持ち時間 | 2000時間（年間労働時間に相当） |
| 勝敗判定 | 最終的な累積部署成果% |
| 5年目 | 昇進イベント（定数の一部が変数化） |

### ターンごとの大まかな流れ

会話で語られたゲームメイクの想定：

- **1〜4・5年目**：トライアンドエラーで「何が変数か」を探る探索フェーズ
- **6〜9年目**：見抜いた変数にリソースを集中する活用フェーズ
- **10年目**：その過程を周りに説明する（※今回の設計では演出として配置。得点化はしない）

---

## 3. アクティビティ（時間の振り先）

毎年2000時間を以下に配分する。各アクティビティには「1回あたりの所要時間」と「制約」がある。

| アクティビティ | 1回あたり | 制約 | 役割 |
|--------------|----------|------|------|
| 会議 | 2時間 | 最低200回（=400時間）必須 | ダミー寄り。係数は小さい |
| 資料作成 | 任意時間 | なし | 弱い交差項を持つ（後述） |
| 現場訪問 | 8時間 | なし | 信頼ptを稼ぐ + 成果係数を持つ |
| VA提案 | 4時間 | なし | 成果の主力。ただし信頼ptゲートあり |
| 報告 | 任意時間 | なし | 信頼ptを稼ぐ。直接成果には効かない |

> **制約の例**：「会議は最低200回」のような縛りは、中盤以降の上申フェーズ（相互確認面談）で一定の信頼ptと成果があれば解除できる。

---

## 4. 成果関数の設計

### 4.1 基本構造

その年の成果は、おおよそ以下の形で決まる：

```
基礎成果 = Σ（各アクティビティの投入時間 × その係数）＋ 交差項
最終成果 = 基礎成果 × ランダム係数
```

### 4.2 係数の設計例（プレイヤーには非公開）

数値はあくまで一例。チューニング前提の初期値として：

| 要素 | 係数 | 分類 | 設計意図 |
|------|------|------|---------|
| 部署の人数 | — | **定数**（自分では変えられない） | 序盤は触れない。昇進で変数化 |
| 会議の回数 | 0〜0.5 | ほぼ定数（ダミー） | 「縛りがあるから埋めるだけ」の罠 |
| 資料作成 | 1.0 | 弱い変数 | 単体では小さいが交差項を持つ |
| 現場訪問 | 2.0 | 中程度の変数 | 信頼ptも稼げる優等生 |
| VA提案 | 5.0（ゲート開放時） | **真の主力変数** | 集中すべき正解だが前提条件が重い |
| 報告 | 0 | 定数（直接成果にはゼロ） | だが信頼ptの源泉という罠 |

> Aさんの言う「係数の大きい変数を見極めてそこにリソースを集中する」の正解は **VA提案**。ただしそれを成立させる前提条件（信頼pt）が隠れているのがミソ。

### 4.3 交差項（要素同士の絡み）

線形和ではなく、要素が互いに影響し合う：

- **資料作成 → 会議**：資料作成に時間をかけると、会議の係数が *多少* 底上げされる。ただし大きくは増えない（ダミーに騙させるための罠）。
- **信頼pt → VA提案**：信頼ptが一定値に達するまで、VA提案の係数は立ち上がらない（ゲート）。報告・現場訪問を疎かにしてVA提案だけに全振りしても成果が出ない。

> この「強い交差項」が、プレイヤーを「VA提案の係数が低い＝VA提案は定数なんだ」と誤認させる。実際にはゲートが閉じていただけ。ここが推定の沼。

---

## 5. ノイズと信頼ポイント（このゲールの心臓部）

### 5.1 ランダム係数

各年の最終成果には、偶然の要素として **0.8〜1.2 のランダム係数** が掛けられる。

これにより1年のデータは±20%のブレを持ち、1回の試行では係数を読み取れない。同じ配分を繰り返して平均を取れば精度は上がるが、それはターンの消費を意味する。

### 5.2 信頼ポイントがノイズ幅を縮める ★中核メカニクス

**信頼ptが高いほど、ランダム係数の振れ幅が小さくなる。**

| 信頼ptの状態 | ランダム係数の幅 | 解釈 |
|------------|----------------|------|
| 低い | 0.8〜1.2（±20%） | 周囲が不安定で、成果がブレる／何が効いてるか見えない |
| 中程度 | 0.9〜1.1（±10%） | 協力が安定し始め、観測精度が上がる |
| 高い | 0.95〜1.05（±5%） | 周囲が安定して協力。データが信用できる |

> イメージ式：`振れ幅 = 0.2 × (1 − 信頼pt正規化値)` のような単調減少関数。

### 5.3 信頼ポイントの三役

この一つのリソースが、会話で挙がった要素を全部つなぐ：

1. **VA係数のゲート**（交差項）— 信頼が一定値を超えるとVA提案の係数が立ち上がる
2. **観測精度の向上**（沼の緩和装置）— 信頼が高いほどノイズが縮み、係数が見えやすくなる
3. **上申のゲート**（制約解除）— 信頼と成果が一定以上で、会議回数などの縛りを外せる

> テーマ的な含意：**信頼を疎かにすると、成果が出ないだけでなく、何が効いているのかすら見えなくなる。**

### 5.4 信頼ポイントの収支

信頼ptは「今年の成果を削って未来に投資する」遅延報酬リソース。

| | 内容 |
|---|------|
| **貯まる** | 報告・現場訪問に時間を割く（その分、直接成果は犠牲になる） |
| **効く** | VA係数ゲート開放／ノイズ縮小／上申ゲート開放 |
| **トレードオフ** | 貯めるのに時間を使うと、その年の直接成果が下がる |

これがメインの時間配分とぶつかり合うのが「二重管理」の本当の面白さ。

---

## 6. 毎年のフィードバック設計

勝敗は最終成果%のみで決まるが、毎年プレイヤーに見せる情報は別問題。沼派の設計なので、総合点だけをポンと出すとプレイヤーは交差項に気づく前に10ターンが終わる。

そこで **部分的なヒント** を出す——ただしそのヒント自体にもノイズを乗せる：

- 「今年はVA提案がよく効いた手応えがある」のような **定性的シグナル**
- 同僚・上司のセリフによる示唆（「最近現場の声が届くようになった気がする」等）
- ヒントの信頼度自体が、信頼ptの高さに連動する（信頼が低い年のヒントは曖昧 or ミスリード）

---

## 7. 特殊フェーズ

### 7.1 上申フェーズ（相互確認面談）

- **発動条件**：信頼ptと累積成果が一定以上
- **効果**：「会議は最低200回」などの制約を解除できる
- **演出案**：内輪プレイなら、この部分だけデモンストレーション形式（プレイヤーが上司役に提案を口頭プレゼン）にすると盛り上がる

### 7.2 昇進イベント（5年目）

- それまで **定数だった要素（部署の人数など）が変数に変わる**
- 立場が上がることで、操作できるパラメータが増える
- ゲーム後半の戦略空間が広がり、探索フェーズで得た知見の応用先が増える

---

## 8. ターン進行の数値シミュレーション例

具体的なプレイ感を掴むための一例（係数は4.2のもの）。

### 1年目：とりあえず均等に振ってみる（探索）

| 配分 | 時間 |
|------|------|
| 会議 | 400h（200回・制約ぎりぎり） |
| 資料作成 | 400h |
| 現場訪問 | 400h（50回） |
| VA提案 | 400h（100回） |
| 報告 | 400h |

- 信頼pt：低い → ノイズ ±20%
- VA提案ゲート：**まだ閉じている**（信頼不足）→ VA係数が立たず、400時間がほぼ無駄に
- 結果：成果が伸びず、しかもノイズが大きいので「VA提案は効かないのかも」と誤認しやすい ← **罠にハマるパターン**

### 2〜3年目：信頼ptへの投資（種まき）

報告・現場訪問の比率を上げる。直接成果は微減するが、信頼ptが中程度へ。

- ノイズが ±10% に縮小 → データが見やすくなる
- VA提案ゲートが開き始める → ここで「VA提案を増やすと急に効く」ことに気づければ勝ち筋が見える

### 6〜9年目：VA提案に集中（活用）

信頼ptを維持しつつVA提案へリソース集中。係数5.0が効き、ノイズも小さいので安定して高成果。

### 10年目：説明フェーズ

過程を言語化して締める（演出）。

> **設計上の狙い**：1年目で「VA提案は効かない」と早合点したプレイヤーほど、信頼ptゲートの存在に気づかず低成果に終わる。逆に「効かないのは前提条件が足りないのでは?」と疑えたプレイヤーが、種まきフェーズを経て勝つ。

---

## 9. チューニングで触るべきパラメータ一覧

実装・調整段階で動かす変数：

- 各アクティビティの係数（4.2）
- 交差項の強さ（資料→会議の底上げ幅、信頼→VAゲートの閾値）
- ノイズの基本幅（±20%）と、信頼ptによる縮小カーブ（5.2）
- 信頼ptの獲得レート（報告・現場訪問1時間あたり何pt）
- 上申・昇進の発動閾値
- フィードバックのヒント精度と信頼pt連動度

---

## 10. テーマとの接続

このゲームが伝えるメッセージ（本の一節より）：

> それまで定数だった社員一人一人の意識が、大きな変数となった。

ゲーム内では「昇進で定数が変数になる」という形で直接的に表現される。さらに「信頼を軽視すると成果も観測精度も失う」という構造を通じて、**周囲との関係そのものが成果を左右する隠れた変数である**ことを体験させる。

ダミー要素（効くと思ったら効かない、効かないと思ったら前提次第で効く）は、現実の **生存者バイアス** のメタファーでもある。

## 付録：初期コンセプトから実装への対応メモ

> ⚠️ ここから下は原本の一部ではなく、**後から付け足した注釈** です。上のコンセプトが実際のアプリ（[`src/`](../src)）でどう実現・変更されたかを対応づけます。数値の出典は [`src/game/config.ts`](../src/game/config.ts)。

| コンセプト（本文の項） | 実装での扱い | おもな参照（config.ts） |
|---|---|---|
| 全10ターン／10年目は説明フェーズ（§2） | **1〜9年目を得点プレイ、10年目はエンディング（種明かし・非得点）** に整理 | `PLAY_YEARS = 9` |
| 昇進で「部署の人数」が定数→変数化（§7.2・§10） | 新アクティビティ **「育成」** として具体化。育成が「チーム意識＝部署の力」を 1.0→最大1.6 へ底上げ（翌年以降に効く遅延報酬） | `develop` / `AWARENESS_BASE` `AWARENESS_MAX` `DEVELOP_RATE` |
| 係数の大小関係（§4.2） | 比率を保ったまま「1時間あたり」にスケール：会議 0.003 ／資料 0.006 ／現場訪問 0.012 ／VA 0.03 ／報告 0 | `COEF` |
| 資料→会議の弱い交差項（§4.3） | 資料の投入時間で会議係数を「多少」底上げ（600h で最大） | `meetingDocsBoost` `docsBoostFullHours` |
| VA提案の信頼ゲート（§4.3・§5.3） | 信頼正規化 0.3 未満は立たず、0.65 で全開 | `VA_GATE_START` `VA_GATE_FULL` |
| ノイズ ±20%→±5%（§5.1・§5.2） | 信頼に応じて単調減少 | `NOISE_MAX = 0.2` `NOISE_MIN = 0.05` |
| 信頼ptの収支（§5.4） | 報告 0.08pt/h・現場訪問 0.04pt/h で蓄積。さらに **自然減衰 0.12/年 を新設**（貯めっぱなしで安泰にならない＝二重管理を強化） | `REPORT_TRUST_RATE` `VISIT_TRUST_RATE` `TRUST_DECAY` |
| 上申で会議制約を解除（§7.1） | 発動条件を数値化：信頼正規化 ≥ 0.6 かつ 累積成果 ≥ 55 で、会議の最低200回制約を解除 | `PETITION_TRUST_NORM` `PETITION_CUM_OUTCOME` `MEETING_MIN_COUNT` |
| 勝敗は最終累積成果のみ（§1・§2） | 累積成果を **S〜D のランク**（しきい値 230／180／130／80／0）に変換し、種明かしと共に提示 | `GRADES` |
| 信頼に連動した精度のヒント（§6） | 毎年のフィードバック生成として実装 | [`src/game/hints.ts`](../src/game/hints.ts) |

### コンセプトから「増えた／変わった」主なもの

- **育成アクティビティ**：昇進の抽象的アイデア（定数の変数化）を、プレイヤーが実際に操作できる具体的な行動へ落とし込んだ。
- **信頼ptの自然減衰**：一度貯めれば安泰、にならないようにして、終盤までトレードオフが続く設計にした。
- **S〜D の評価**：単一の累積%だけでは達成感が伝わりにくいため、ランクと講評（種明かし）を付与した。
