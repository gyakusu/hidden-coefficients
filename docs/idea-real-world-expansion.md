## 1. 一定ではない係数①：累積サチュレーション（競合調査）

> ⚠️ **本節は改訂により破棄**。「競合他社の分析」は例え話であり、新アクティビティを追加する意図はなかった（フィードバックの誤読）。
> 累積サチュレーションのメカニクス自体は **現場訪問へ吸収** する形で存続する。改訂後の設計は [`design-revision-2026-07.md`](./design-revision-2026-07.md) §1 を参照。
> 以下は当時の記録として原文のまま残す。

### 1.1 メカニクス

新アクティビティ **「競合調査」（research）** を追加する。1回あたり8時間・制約なし。

ポイントは、成果への寄与を **その年の投入時間ではなく、ゲーム開始からの累積投入時間** で決めること：

```
知識ストック K = 1 − exp(−累積調査時間 / RESEARCH_TAU)
その年の調査寄与 = RESEARCH_COEF_MAX × (K_今年末 − K_年初)   … フロー型（差分が効く）
```

- `RESEARCH_TAU ≈ 120h` 程度にすると、**初年度に100〜150h入れれば知識ストックの6〜7割が埋まる**。2年目に同じ時間を入れても得られる差分は残りわずか——「最初の1回は意味があるが、2回目以降はほぼ意味を為さない」を数式そのもので表現できる。
- 差分（フロー）ではなく水準（ストック）を毎年効かせる変種も考えられるが、「毎年少し効き続ける」となり指摘の趣旨（2回目以降は無意味）から外れるため、**フロー型を推奨**。

### 1.2 成果ではなく「情報」で返す変種（推奨・併用可）

競合調査の報酬を成果%ではなく **観測精度** で返す案。こちらの方が現実の「調査」の性質に近い：

- 知識ストック K に応じて、**翌年以降の結果画面で見える情報の解像度が上がる**（例：K ≥ 0.5 で「今年のランダム係数のおおよその符号」が開示される、K ≥ 0.8 で寄与内訳の上位1項目が実名で見える）。
- 信頼ptによるノイズ縮小（±20%→±5%）が「観測のブレそのものを減らす」のに対し、調査は「ブレの事後的な読み解きを助ける」——似て非なる2系統の情報投資になり、二重管理に厚みが出る。

### 1.3 プレイ体験上の狙い

1年目に調査へ振ったプレイヤーは「調査は係数が大きい変数だ」と学習する。2年目に同じ配分をして **裏切られる**。ここで「係数は定数ですらなく、状態の関数だ」という一段深い気づきに至る。VA提案の罠（前提待ち）と合わせ、**「1年のデータで係数を断定するな」というゲームの主題を両方向から補強**する。

### 1.4 追加するチューニング項目（config.ts）

```ts
UNIT_HOURS.research = 8
RESEARCH_TAU = 120          // 知識ストックの飽和速度
RESEARCH_COEF_MAX = 6       // フロー型のとき、K の差分1.0あたりの成果
RESEARCH_INFO_TIER_1 = 0.5  // 情報開示の閾値（ランダム係数の符号）
RESEARCH_INFO_TIER_2 = 0.8  // 情報開示の閾値（寄与上位1項目）
```

`GameState` に `researchCumHours`（累積調査時間）を持たせるだけで実装できる。engine は純粋関数のまま。

## 2. 一定ではない係数②：資料作成の凹関数化（品質カーブ）

### 2.1 メカニクス

現行の資料作成は線形（`0.006 × 時間`）。これを **飽和曲線** に置き換える：

```
資料の寄与 = DOCS_VALUE_MAX × (1 − exp(−資料時間 / DOCS_TAU))
```

`DOCS_TAU ≈ 150h`、`DOCS_VALUE_MAX ≈ 2.4` とすると：

| 投入時間 | 寄与 | 1時間あたり |
|---------|------|------------|
| 100h | 約1.17（49%） | 0.0117 |
| 300h | 約2.08（86%） | 0.0069 |
| 600h | 約2.36（98%） | 0.0039 |
| 1000h | 約2.40（100%） | 0.0024 |

「1hで80%、3hで90%」の構造がそのまま出る。**序盤の傾きは現行係数の約2倍、大量投入時は半分以下**——資料は「少し作るのは正解、作り込むのは悪手」という現実の手触りになる。

### 2.2 交差項との整合

現行の「資料→会議の底上げ」交差項（`docsBoostFullHours = 600h`）は残す。ただし飽和点を資料本体（150h）より遅く（600hのまま）しておくと、**「資料を作り込む理由が一応ある（会議が楽になる）が、それでも見合わない」** という現実的な誘惑が生まれる。ダミー罠としてより意地悪に機能する。

### 2.3 他アクティビティへの展開（任意）

現場訪問にも弱い凹性（`VISIT_TAU ≈ 700h` と緩め）を入れると「全部curveなんだ」と一般化でき、推定問題が「傾きの推定」から「**曲線の形の推定**」に進化する。ただし一度に全部を非線形化すると難度が跳ねるため、**第1弾は資料作成のみ**を推奨（VA提案は主力のご褒美なので線形のまま残し、「集中投資が報われる唯一の変数」として際立たせる）。

## 3. 会社マターで決まらない要素：市況係数と評価の二軸化

### 3.1 メカニクス：市況係数（macro）

毎年の最終成果に、**プレイヤーの行動と完全に独立な「市況係数」** を掛ける：

```
最終成果 = 基礎成果 × チーム意識 × ランダム係数(信頼で縮む) × 市況係数(縮められない)
```

市況係数は平均回帰するAR(1)過程で生成する（好況・不況が数年単位でうねる）：

```
market[t] = 1 + MACRO_PERSIST × (market[t−1] − 1) + ε,  ε 〜 U(−MACRO_STEP, +MACRO_STEP)
初期値 1.0、範囲 [1 − MACRO_RANGE, 1 + MACRO_RANGE] にクランプ
例: MACRO_PERSIST = 0.6, MACRO_STEP = 0.1, MACRO_RANGE = 0.25
```

### 3.2 設計上の要点：**ノイズと違い、絶対に縮まない**

既存のランダム係数は「信頼を積めば±5%まで縮む＝努力で制御できる不確実性」。市況係数は **どれだけ信頼を積んでも縮まない不確実性** として対置する。この非対称こそが指摘2のメッセージ：

> 制御できる不確実性は制御しろ。制御できない不確実性は、制御できないと知れ。

### 3.3 部分的に観測可能にする（ニュース演出）

市況を完全に隠すと単なる追加ノイズになり、推定が理不尽化する。そこで **年初に「ニュース」として方向だけ開示** する：

- 「円安が進行。輸出環境は追い風」（market > 1.1）
- 「景気後退の足音。市場は冷え込み気味」（market < 0.9）
- 「大きな動きなし」（それ以外）

方向は分かるが大きさは分からない。プレイヤーは「今年の好成績はどこまで自分か？」を自問することになる。

### 3.4 評価の二軸化：素点と実力点

エンディングの評価を2つ表示する：

| 軸 | 定義 | 意味 |
|----|------|------|
| **素点（結果）** | 累積の最終成果（市況込み） | 世間が見る数字。運も込み |
| **実力点（市況調整後）** | 各年の成果を市況係数で割り戻した累積 | 「もし市況が平年並みだったら」の反実仮想 |

- ランク（S〜D）は **実力点で判定** する。市況で運良く伸びた素点は讃えず、市況に沈められた良プレイは正当に評価する。
- エンディングの種明かしで両者を並べ、乖離が大きい場合に専用のメッセージを出す：
  - 素点 ≫ 実力点：「追い風の10年だった。この数字のすべてが、あなたの実力ではない。」
  - 素点 ≪ 実力点：「向かい風の10年だった。この数字の低さは、あなたのせいではない。やるべきことは、やれていた。」

**「良い成績でも自分のせいではないし、悪い成績でも悔やむべきではない」を、評価システムそのもので語る。** テキストで説教するのではなく、ランク判定のロジックが態度を示す。

### 3.5 追加するチューニング項目

```ts
MACRO_PERSIST = 0.6    // 景気のうねりの持続性
MACRO_STEP = 0.1       // 年ごとの変動幅
MACRO_RANGE = 0.25     // 市況係数の上下限（0.75〜1.25）
MACRO_NEWS_THRESHOLD = 0.1  // ニュースで方向を報じる閾値
```

`YearResult` に `marketCoef` を追加。RNGは既存同様に注入可能にしてテスト決定性を保つ。

## 4. 虚無感を与えないために：年次振り返りシステム

指摘3の核心は「**結果を隠す**のは意図だが、**学習まで見えない**のは意図ではない」と読む。成果のインジケータを増やすのではなく（それは沼の設計を壊す）、**プレイヤー自身の意思決定と学びを可視化する**方向で設計する。

### 4.1 年度末レビュー画面「決算と反省」

各年の結果表示を1画面のイベント「年度末レビュー」に格上げし、3つのブロックで構成する：

**① 決算サマリ（結果の分解・霧つき）**

今年の成果を要因分解して見せる。ただし解像度は信頼pt（と競合調査の知識ストック）に連動：

| 信頼ティア | 見えるもの |
|-----------|-----------|
| low | 最終成果の数字のみ（現行どおり） |
| mid | 「実力分」と「環境・運の分」の2分割（符号のみ、大きさはぼかす） |
| high | 実力分 / 市況分 / 運（ノイズ）分の3分割バー ＋ 寄与上位アクティビティのぼかし表示 |

「情報の解像度も信頼で買う」という既存の中核メカニクスの延長線上に置けるので、設計の一貫性が保てる。

**② プロセス指標（結果に依らない、自分で制御できた指標）**

成果がノイズと市況で汚れていても、これらは汚れない：

- **信頼の推移**：矢印と小さなスパークライン（実数は非公開のまま、傾向のみ）
- **探索度**：昨年と配分をどれだけ変えたか（配分ベクトルの変化量）。「今年は新しい実験をしたか、活用に徹したか」が一目でわかる
- **投資率**：報告・現場訪問・育成・調査など「今年の成果を犠牲に未来に張った時間」の割合
- **市況ニュースとの照合**：「今年は向かい風だった」の再掲（成果が低くても環境要因を思い出せる）

**③ 仮説ノート（このシステムの目玉）**

年度末に1問だけ、プレイヤーに **仮説を宣言** させる：

> 「現時点で、最も成果に効くと思う活動はどれ？」（6択＋「まだ分からない」）

- 回答は保存するだけで、正誤はその場では **一切教えない**（沼は守る）。
- エンディングの種明かしで、**9年分の仮説の変遷を真実と並べて表示**する：

```
1年目: 会議        ✗
2年目: 資料作成    ✗
3年目: まだ分からない
4年目: 現場訪問    △（2番手）
5年目: VA提案     ✓ ←ここで気づいた！
6〜9年目: VA提案   ✓
```

これにより最終画面が「点数の発表」から「**自分の推定が収束していく物語の再生**」に変わる。低スコアでも「4年目に気づけた自分」を発見でき、虚無感の対極——**学習の実感**——が残る。ゲームのジャンルが“システム同定”であることを、プレイヤー自身の推定履歴で証明する仕掛け。

### 4.2 エンディングの拡張

現行の種明かし＋プレイ分析に加えて：

1. **仮説ノートの答え合わせ**（§4.1③）——何年目に真実へ収束したか
2. **二軸評価**（§3.4）——素点と実力点、乖離コメント
3. **反実仮想**：「もしあなたの最終年の配分を1年目から続けていたら（市況・乱数は同一系列で）」のスコアを併記。探索に費やした年数の「授業料」が定量化され、探索と活用のトレードオフを最後に体感できる

### 4.3 実装メモ

- 仮説ノートは `GameState.history` に `hypothesis: ActivityKey | 'unknown'` を足すだけ。エンジン変更は不要で UI（ResultPanel → 年度末レビュー画面化）が主戦場。
- 要因分解は `YearResult` が既に `baseOutcome / randomCoef / contributions` を持っているため、`marketCoef` を足せば材料は揃う。**表示の霧（信頼連動の解像度制御）だけが新規ロジック**。

## 5. 実装フェーズ案

依存関係と価値の出る順に3段階に割る。各フェーズ単体でリリース可能。

| フェーズ | 内容 | 触る場所 | 規模 |
|---------|------|---------|------|
| **P1: 係数の非定常化** | 資料作成の凹化（§2）＋競合調査（§1、まずはフロー型のみ） | `config.ts` / `engine.ts` / `types.ts` / AllocationPanel / テスト | 小 |
| **P2: 市況** | 市況係数＋ニュース演出＋二軸評価（§3） | `engine.ts` / `hints.ts` / EndScreen / テスト | 中 |
| **P3: 振り返り** | 年度末レビュー画面＋仮説ノート＋エンディング拡張（§4） | `useGame.ts` / ResultPanel / EndScreen | 中〜大（UI中心） |

P1 → P2 の順序が重要：市況（さらなる不確実性）を先に入れると推定が理不尽化しかねないが、振り返り（P3）とセットなら「不確実性は増えたが、読み解く道具も増えた」の釣り合いが取れる。**P2 と P3 は近いリリースで揃えるのが望ましい。**

## 6. バランス上のリスクと対策

| リスク | 対策 |
|--------|------|
| 不確実性の源が3つ（ノイズ・市況・非定常係数）になり、9年では推定不能になる | 市況は方向をニュースで開示（§3.3）。競合調査は情報報酬（§1.2）で「読み解き力」も同時供給。`engine.test.ts` のキャリブレーション（上級 > 均等 > 罠）に市況系列固定のケースを追加して担保 |
| 競合調査が「1年目に必ず取る」だけの固定手順（作業）になる | 調査の初年度リターンを VA開通後の VA より弱くしておく（最適解は「早めに少し」であって「全振り」ではない）。＋機会費用として信頼投資と競合させる |
| 資料の凹化で資料が「序盤の正解」になりすぎる | `DOCS_VALUE_MAX` を現場訪問600h分程度に抑え、飽和後は完全に頭打ちにする |
| 実力点評価が「市況を読む楽しみ」を消す | ランクは実力点、ただし素点も大きく表示して「世間の評価」として演出。市況を読んで配分を寄せる上級プレイ（好況年に成果型へ、不況年に投資型へ）は素点側で報われる |
| 振り返りの情報量が増えて種明かしのカタルシスが薄れる | 年次レビューでは正誤・係数値は一切出さない（プロセス指標と霧つき分解のみ）。真実の開示はエンディングに温存 |

## 7. テーマとの接続（まとめ）

拡張後、このゲームが語るメッセージは3層になる：

1. **係数は隠れている**（現行）——何が効くかは誰も教えてくれない
2. **係数は定数ですらない**（P1）——昨日効いたことが今日も効くとは限らない。逓減を見抜き、80点で止める勇気を持て
3. **係数の外側がある**（P2/P3）——市況はあなたの変数ではない。結果ではなく意思決定の質を振り返れ。良い年に驕らず、悪い年に折れず

原作の一節「それまで定数だった社員一人一人の意識が、大きな変数となった」に対し、この拡張は対になる命題——**「変数だと思っていたものが、もう定数になっていることもある。そして、どうやっても変数にできないものもある」**——を足すものになる。
