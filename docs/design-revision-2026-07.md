# 設計改訂（2026-07）：「競合調査」の吸収と、"やってみないと分からない"の原則化

> ゲームデザイナーからのフィードバック再確認を受けた **中規模の設計見直し**。
> 前回の拡張設計（[`idea-real-world-expansion.md`](./idea-real-world-expansion.md)）のうち §1「競合調査」はフィードバックの **誤読に基づく設計** だったため、本ドキュメントで改訂する。
>
> **実装状況（2026-07）：本改訂の §5 全タスクをアプリへ実装済み。** 競合調査（`research`）アクティビティを削除し、
> 累積サチュレーションを現場訪問へ吸収（`visitCumHours` / `VISIT_TAU` / `VISIT_VALUE_MAX`）、情報報酬を訪問ストックへ付け替え、
> 仮説ノートに「来年も同じだけ効くか（how）」の2問目を追加した。キャリブレーションテストも6項目構成で更新済み。

## 0. 何を読み違えたか

### 0.1 誤読と真意

| | 前回の解釈（誤） | デザイナーの真意（正） |
|---|---|---|
| 「競合他社の分析は1回目だけ意味がある」 | 新アクティビティ **「競合調査」を追加** し、その項目に累積サチュレーションを実装する | 競合分析は **あくまで例え話**。新しい項目を作る意図はなく、この性質は **既存の項目のどれかに吸収** されるべきもの |
| 指摘の射程 | 特定の1項目（調査系）の仕様の話 | **既存の項目すべてに関わる原則** の話：「どの項目に時間を振るか、それがどう影響するかは、やってみないと分からない」 |

つまりデザイナーが伝えたかったのは「調査という行動を足してほしい」ではなく、

> **効き方（係数の形）は項目ごとに違い、しかも事前には分からない。振ってみて初めて分かる。**

という、このゲームの推定対象そのものを一段深くする原則だった。

### 0.2 なぜ「新項目の追加」は設計としても誤りだったか

誤読の産物というだけでなく、新項目の追加はこのゲームのコアを3点で毀損していた：

1. **項目の追加はシグナリングになる**。アップデートで「競合調査」という項目が増えれば、プレイヤーは「これは特別な項目だ、試すべきものだ」と告知されたに等しい。「何が効くかは誰も教えてくれない」という体験の核（非対称性）を、メニュー構造そのものが裏切る。
2. **探索空間が広がりすぎる**。9年しかない探索予算に対して配分先が7つに増えると、全項目を一度ずつ試すだけで序盤が終わり、「形の発見」まで到達できない。
3. **性質と項目が1対1に固定される**。「飽和するのは調査、凹むのは資料」とラベルが貼られた瞬間、プレイヤーの学びは「項目の暗記」になる。真意は逆で、**どの項目がどんな形で効くかこそが隠すべき構造** である。

### 0.3 影響範囲

- 前回拡張の **§1（競合調査の新設）は破棄**。累積サチュレーションのメカニクス自体は正しい道具なので、既存項目へ吸収する（§1）。
- 前回拡張の **§2（資料の凹化）・§3（市況）・§4（振り返り）は存続**。ただし §4 は「やってみないと分からない」の原則に合わせて問いを拡張する（§3.3）。
- アクティビティ数は **6項目（会議・資料作成・現場訪問・VA提案・報告・育成）に戻す**。

## 1. 累積サチュレーションの吸収先：現場訪問

### 1.1 吸収先の検討

「1回目は大きな意味があるが、繰り返しても同じだけは返ってこない」性質を、どの既存項目が担うべきか：

| 候補 | 適合 | 判断 |
|------|------|------|
| 会議 | ✗ ほぼ定数のダミーであることが役割。飽和以前に効かない | 変更しない |
| 資料作成 | △ すでに年内飽和の凹化（前回拡張 §2）を持つ。二重に持たせると役割が濁る | 変更しない |
| **現場訪問** | ◎ 「現場を初めて知る」学びはまさに競合・市場分析の例え話が指していたもの。初回の訪問は世界の見え方を変えるが、100回目はルーティン | **吸収先に採用** |
| 報告 | ✗ 成果ゼロ・信頼の源泉という罠が役割 | 変更しない |
| 育成 | ✗ 遅延報酬という固有の形をすでに持つ | 変更しない |

現実の対応もきれいに繋がる：競合他社の分析・市場を見に行く・顧客の現場に立つ——これらは全部「**外を見て世界の解像度を上げる行動**」で、ゲーム内ではもともと現場訪問がその席にいる。例え話を項目化するのではなく、例え話が指していた席に性質を返す。

### 1.2 新しい現場訪問の仕様

成果への寄与を「その年の投入時間 × 一定係数」から、**ゲーム開始からの累積投入時間で決まる知識ストックの差分** に置き換える：

```
知識ストック K = 1 − exp(−累積訪問時間 / VISIT_TAU)
その年の成果寄与 = VISIT_VALUE_MAX × (K_今年末 − K_年初)   … フロー型
信頼の獲得     = VISIT_TRUST_RATE × その年の訪問時間        … 従来どおり線形（変更なし）
```

**信頼獲得は線形のまま残す** のが要点。これにより現場訪問は「効かなくなる」のではなく「**役割が変わる**」——序盤は成果と信頼の両取りができる優等生、飽和後は信頼維持のための行動へ。プレイヤーが発見するのは「現場訪問は罠だった」ではなく「同じ項目でも、時期によって振る理由が変わる」という一段深い事実になる。

### 1.3 パラメータ案

序盤の手触りを現行実装（線形 0.012/h）から大きく変えず、繰り返しで逓減が現れる値：

```ts
VISIT_TAU = 600        // 累積600hで知識ストックの63%が埋まる
VISIT_VALUE_MAX = 12   // K の差分 1.0 あたりの成果。初期傾き 12/600 = 0.02/h
```

毎年600hずつ振り続けた場合の成果寄与：

| 年 | 累積時間 | K（年末） | その年の寄与 | 1時間あたり |
|----|---------|----------|------------|------------|
| 1年目 | 600h | 0.63 | 約7.6 | 0.0126 |
| 2年目 | 1200h | 0.86 | 約2.8 | 0.0047 |
| 3年目 | 1800h | 0.95 | 約1.0 | 0.0017 |
| 4年目 | 2400h | 0.98 | 約0.4 | 0.0006 |

1年目はほぼ現行の線形と同じ体験（むしろわずかに強い＝誘惑）。同じ配分を繰り返した2年目に **裏切られる**。「効いた配分をもう一度」が通用しない——まさに「やってみないと分からない」し、**やってみた結果すら来年の保証にならない**。

### 1.4 情報報酬の引き継ぎ

前回拡張 §1.2 の「調査は観測精度で返す」という案は、知識ストック K にそのまま引き継ぐ：

- K ≥ 0.5：結果画面でその年のランダム係数のおおよその符号が開示される
- K ≥ 0.8：寄与内訳の上位1項目が実名で見える

信頼pt（ブレそのものを縮める）と現場の知識（ブレの読み解きを助ける）という **似て非なる2系統の情報投資** の構図は保たれる。新項目なしで、二重管理の厚みだけが残る。

### 1.5 罠の対称性テーブル（改訂版）

| 罠 | 見え方 | 真実 | 学び |
|----|--------|------|------|
| VA提案 | 効かない | ゲートが閉じていただけ | 「効かない」の裏に前提条件を疑え |
| **現場訪問（改訂）** | 序盤めちゃくちゃ効く優等生 | 成果面は飽和する。残るのは信頼の役割 | 「効いた」は再現するとは限らない。項目の役割は時期で変わる |
| 資料作成 | 時間をかけるほど良くなる | 最初の1時間で8割が出る | 追加投入の限界効用を見よ |
| 市況 | 成果が良い＝自分の手柄 | 半分は環境が決めた | 結果と意思決定の質を分けて評価せよ |

## 2. 原則化：「やってみないと分からない」

### 2.1 6項目・6つの応答形状

競合調査を吸収した結果、偶然ではなく設計として、**6つの項目がすべて異なる「効き方の形」を持つ** ことになる（すべてプレイヤーには非公開）：

| 項目 | 応答の形（真実） | 発見に必要な実験 |
|------|----------------|----------------|
| 会議 | ほぼゼロの線形（資料交差項でわずかに底上げ） | 制約以上に増やしてみる／資料と組み合わせる |
| 資料作成 | **年内で速く飽和する凹**（150hで63%） | 少量と大量を別の年に試す |
| 現場訪問 | **年をまたいで飽和する凹**（累積ストック）＋信頼は線形 | 同じ配分を2年続けてみる |
| VA提案 | **信頼ゲート付き線形**（開けば最強） | 信頼を積んでから再試行する |
| 報告 | 成果ゼロ・信頼線形 | 成果との相関を疑い、翌年への効果を見る |
| 育成 | **遅延線形**（翌年以降のチーム意識に効く） | 振った年ではなく翌年を観察する |

ゼロ・弱線形・年内凹・累積凹・ゲート・遅延——**同じ「効き方」がひとつもない**。だから「この項目は試した、係数はこれくらい」という1回の観測では形を確定できず、「どの項目に時間を振るか、それがどう影響するか」は文字どおり **振ってみないと、しかも振り方を変えてみないと** 分からない。

### 2.2 設計原則（今後の拡張・チューニングの憲法）

今回の誤読の再発防止も兼ねて、原則として明文化する：

1. **効き方の形は項目ごとに異なり、事前に開示しない。** 項目名・UIラベル・ヘルプで曲線タイプを示唆しない（「調査」のような、情報系だと分かる名前の項目を足さない）。
2. **メカニクスの追加を項目の追加で行わない。** 新しい性質は既存項目への吸収を第一候補にする。項目リスト自体がプレイヤーへの告知になるため。
3. **形の発見は「配分を変える実験」によってのみ起こる。** 同じ配分の反復はノイズを均せても形は見せない（凹も飽和も遅延も、変化させて初めて観測できる）。探索にはノイズ対策と別の価値がある。
4. **昨年の結論は今年の保証ではない。** 非定常な項目を少なくとも1つ置き、「学習した戦略に安住させない」圧を維持する。ただし全項目を非定常にはしない（推定不能になる。§4）。

### 2.3 振り返りシステムへの波及

前回拡張 §4 の仮説ノートは「最も効く活動はどれ？」という **どれ（which）** の問いだった。原則に合わせて **どう（how）** の問いを加える：

> 「現時点で、最も成果に効くと思う活動はどれ？」（6択＋分からない）
> 「その活動は、来年も同じだけ効くと思う？」（効く／弱まる／分からない）

エンディングの答え合わせで2問目も並べると、「VA提案と気づいたのは5年目、**現場訪問の飽和に気づいたのは3年目**」のように、*which* と *how* の2軸で推定の収束が物語られる。プロセス指標の「探索度」（配分ベクトルの変化量）は、原則3の「変化させた者だけが形を見られる」を支える指標として位置づけを格上げする。

## 3. ゲーム全体の語り直し

この改訂後、ゲームのメッセージは次の3層になる（前回拡張 §7 の改訂版）：

1. **係数は隠れている**（原設計）——何が効くかは誰も教えてくれない
2. **係数には形がある**（本改訂）——線形とは限らない。飽和する、凹む、遅れる、前提を待つ。どの項目がどの形かは、振り方を変えてみないと分からない
3. **係数の外側がある**（市況・存続）——あなたの変数ではないものがある。結果ではなく意思決定の質を振り返れ

原作の「定数だった社員一人一人の意識が、大きな変数となった」に対して、本改訂が足す命題は：

> **変数の係数は、表を見ても分からない。振ってみた者だけが、その形を知る。**

## 4. バランス上の論点と対策

| 論点 | 対策 |
|------|------|
| 現場訪問が飽和すると中盤以降の配分先が痩せる | 信頼獲得（線形）が残るため完全な死に枠にはならない。信頼の自然減衰（0.12/年）との組み合わせで「維持のための訪問」に意味が残る |
| 序盤の現場訪問が強すぎて1年目の正解が固定化する | 初期傾き（`VISIT_VALUE_MAX / VISIT_TAU`）を現行線形の1.5〜2倍以内に抑える。1年目に全振りしても、信頼投資を怠ればVAゲートが遠のく機会費用で相殺される |
| 非定常項目が2つ（資料=年内凹、現場=累積凹）で9年では推定不能になる | 形の異なる凹を「年内」と「年跨ぎ」に分離してあるため、観測上は混ざらない。知識ストックの情報報酬（§1.4）が読み解き力を同時供給する |
| 「同じ配分を繰り返して平均でノイズを消す」戦略が完全に死ぬ | 意図的なトレードオフとして許容する。反復は依然ノイズには有効で、非定常の検出には無効——**反復と変化のどちらに年を使うか** が新しい選択になる |
| 既存プレイヤー（実装済み版）の学習が無効になる | 競合調査の削除は項目リストの変化として即座に伝わる。パッチノートでは「調査は現場訪問に統合」とだけ告げ、飽和の仕様は書かない（原則1） |
